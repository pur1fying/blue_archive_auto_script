# BAAS 配置任务测试工具

使用与 `main.service.py` 相同、已安装 service 依赖的 Python，在仓库根目录运行。
导入 `tests`、列出任务、运行 self_tests 均不会执行游戏任务。
测试工具自产日志、提示、任务名称和报告界面使用英文。配置名、实际游戏窗口标题、配置快照和原始任务日志保留原文；取证内容不做翻译。

```powershell
python -m tests --list-configs
python -m tests --list-tasks
python -m tests
```

交互入口先选择原配置，再为每个配置选择任务和顺序。输入 `RUN` 后才启动真实任务。
任务直接复用 service 的完整初始化、当前注入和 `ServiceRuntime.solve_task`，不复制游戏操作步骤。
设备初始化和任务执行由同一个 service 工作线程顺序完成。测试工具仅在原初始化返回后核对目标身份、安装取证记录；不会提前在测试线程初始化设备。报告 JSON 中记录 `initialization_thread` 和 `execution_thread`，用于核对线程归属。
任务参数、次数、游戏内购买设置来自原配置，运行结果正常写回原配置。不会自动安装依赖、更新代码或购买额外资源，不涉及真实支付。

## 保存和复用计划

```powershell
python -m tests --save-plan my-plan.json
python -m tests --plan my-plan.json --check
python -m tests --plan my-plan.json
# 明确确认计划中的全部真实操作，适用于非交互终端：
python -m tests --plan my-plan.json --yes
```

计划格式见 `fixtures/example-plan.json`。`config_id` 是 `config/` 下的实际目录名；任务 ID 来自当前 `func_dict`。
`fixtures/selected-client-plan.json` 保存本次选定的 cn、global、jppc 各 15 项任务。`collect_reward` 与 `collect_daily_power` 当前调用同一实现，按清单分别执行。
每个配置只能出现一次，其任务列表可显式重复任务。每项默认执行一次，函数内部次数仍遵循原配置。
全局 `task_timeout_seconds` 默认 1800；单个配置可使用 `timeout_seconds` 覆盖。
`--check` 只查询窗口、设备和已有 BAAS 后端的占用状态，不初始化游戏控制或执行任务。

## 并发与停止

- 各配置按自己的任务顺序运行。两个桌面客户端共用桌面锁，覆盖初始化、截图、输入、执行和取证。
- 独立模拟器可与桌面端并行。同设备不同配置互斥；无法证明设备独立时保守串行。
- 请先打开并登录所需客户端。窗口缺失、存在多个同名目标、已有自动化占用或占用状态无法确认时会阻塞，不抢占窗口或关闭别的进程。
- 程序无法阻止测试开始后人为启动的其他自动化；运行期间不要让其他工具同时控制测试目标。
- 失败、超时或无法安全执行会停止该配置后续任务，其他无冲突配置继续。
- 已明确识别的无资源结果标为“未执行”，继续下一项。第一版覆盖日程无票、悬赏/学园交流未完成扫荡且资源不足、演习未开放、活动入口未适配；其他未适配的无操作结果仍显示“正常结束／待复核”，不会宣称业务通过。
- Windows 上测试运行期间注册全局 `Ctrl+C`，游戏在前台时也能停止整轮测试，无需切回终端。快捷键注册失败则不启动实机测试，结束后立即注销，恢复正常复制快捷键。
- 按一次即通知所有配置停止，控制读取线程直接设置运行停止标记；两秒内测试后端仍未退出则自动强停，不要求再按一次。第二次按下可立即强停。强停只处理本轮测试进程、同批次 Python 子进程及其新建的 OCR 子进程，并释放可能由拖动遗留的鼠标按键；游戏、模拟器、已有后端及共享 OCR 不会被终止。
- 中止状态和是否强停记录到报告，已完成任务保留结果，未完成任务不能算通过。非 Windows 平台通过测试终端的 Ctrl+C 停止。
- 未退出的任务会保留设备占用，其他需要该设备的任务阻塞。正常退出的测试后端不占用 HTTP/SHM 端口。

## 结果与人工复核

报告保存在 `output/test_runs/<run_id>/report.html`，同时保存机器可读的 `result.json`。
每项记录实际终态、代码版本、目标设备、配置变化、日志和截图。启动接口返回 `ok` 不算任务结束，单条 ERROR 日志也不直接等于任务失败。

“正常结束”只表示生产任务没有失败，默认业务结果为“待复核”。空票、未解锁、领取结果和资源变化等需结合证据确认。
对应报告中的执行状态为 `Completed`，人工复核值为 `pending`、`passed` 或 `failed`。旧报告的中文复核值在读取复核或重新生成报告时会转为这些英文值。

```powershell
python -m tests review <run_id>
```

只允许为正常结束的任务填写业务“通过／不通过”和备注。自动执行状态不会被人工覆盖。

截图从日志发出时的 `latest_img_array` 复制，异步编码写盘。包括首次图像匹配放行帧、OCR 和日程状态日志。
没有截图时明确记为证据缺失；不会另取稳定截图冒充首次帧，也不修改识别函数、参数或返回值。

每次真实任务测试默认收集 OCR 区域证据，不需要环境变量或额外开关。报告中的 `OCR regions` 展示本轮实际执行的全部区域 OCR 调用，包括 `recognize_int` 等上层接口、原始 OCR 区域接口，以及能追溯到原图的直接裁剪输入。
在 OCR 调用开始时复制完整原图，保留区域坐标、源码调用位置、识别结果或异常；同一张原图上的多个区域合并到一张标注图，例如 AP、Credit Points、Pyroxene 同时圈出。
标注图固定为 1280×720；源图本身为 720p 时保持像素不变，只在独立副本上画框。其他分辨率单独保留原尺寸截图，按实际裁剪像素范围映射到 720p，并明确标记缩放，避免与原生 720p 混淆。
原图、标注图和每帧 JSON 位于各任务的 `ocr/` 子目录，完整调用记录为 `ocr/calls.jsonl`。图片编码和标注在证据写入线程执行，不增加截图、点击、重试或 sleep。
未触发 OCR 的任务显示 `not_observed`；丢图、写入失败或已经变换且无法追溯原图坐标的独立裁剪显示 `incomplete`，不会猜测区域或冒充完整覆盖。OCR 模型自检的固定测试图片不属于游戏界面区域。
`captured` 只代表证据已记录，区域位置和识别结果是否正确仍需结合标注图复核。

每轮测试还会全量静态扫描当前项目，生成 `ocr-inventory.html` / `ocr-inventory.json`，列出所有业务 OCR 调用位置、区域表达式、CN/Global/JP 分支坐标、动态坐标来源、旧接口疑点，以及本轮 `observed` / `not_observed` 状态。扫描包含被 Git 忽略的 service 源码，不导入或执行业务模块；依赖环境、工作树副本、构建输出及测试产物不作为当前项目源码统计。
一个调用位置可能对应多个服务器或动态区域，`observed` 仅说明本轮调用过该处，不代表所有坐标分支均已验证。引擎内部转发、模型自检和测试示例单独列出。可以独立运行扫描，无需打开游戏：

```powershell
python -m tests.tasks.ocr_catalog
```
任务前后图片标为“最近可用截图”：设备尚未初始化或任务结束后未再取帧时，可能缺失或滞后，需参考事件时间。
截图队列拥塞或写盘失败会显示证据丢失数量。凭据字段及日志中的已知秘密会遮蔽，但真实游戏截图仍含账号信息，请勿直接公开上传。

退出码：0 表示批次执行无程序失败（可能仍有未执行和待复核）；1 表示失败／超时／阻塞；2 表示计划或环境错误；130 表示取消／中断。
第一版不安装 Git 钩子、不修改 CI 或发布流程。

## MuMu 截图压力测试

```powershell
python -m tests.stress.nemu_capture --config cn
# 每组缩短到 5 秒，用于检查工具能否运行：
python -m tests.stress.nemu_capture --config cn --quick
```

该入口只读取截图，不点击、不执行游戏任务，也不保存自动探测到的模拟器路径到原配置。
复用原始 `NemuScreenshot` 三次尝试及 `NemuClient`，在测试进程中记录调用耗时、异常类型和超时后仍在执行的原生调用。
完整测试依次运行：原有 0.3 秒截图间隔 120 秒；无间隔连续截图 90 秒；两个独立连接同时截图 60 秒；将各 IPC 调用超时临时改为 500 ms 连续截图 90 秒。
其余阶段使用原有 150 ms 超时。500 ms 对照覆盖连接、分辨率查询和像素读取，不改变生产代码或配置，也没有新增重试等待。

每个阶段的 `result.json` 每 5 秒更新一次，记录异常堆栈、截图为空的次数、重试恢复次数、P95/P99/最大耗时及内存峰值。
报告保存在 `output/test_runs/nemu-stress-<time>/report.html`，原始 SDK 日志和首张有效截图位于各阶段目录。
连续 20 张无效/空图、测试进程内存超过 1 GiB 或超过看门狗期限时停止该阶段，并保留原因；只清理本次创建的测试进程。
单帧耗时不包含截图间隔，包含生产重试。截图形状和类型有效不代表业务识别正确；近黑画面单独计数，不直接判失败。
静止页面压测不能替代游戏切换、战斗加载等实际任务验收。所有测试工具日志和报告字段使用英文。

真实任务执行时可启用同一条 Nemu 连接的诊断：

```powershell
$env:BAAS_TEST_NEMU_TRACE = '1'
python -m tests --plan my-plan.json --yes
```

该模式从设备初始化后开始记录任务实际使用的截图和触摸调用，不额外截图、点击、添加等待或修改超时参数。
每个任务目录保存 `nemu-trace.json`；记录截图编号、输入时间、异常距最近触摸的时间和原始重试结果。
任务日志保留输入事件、异常前最近有效画面，以及间隔抽样的输入后画面。距离触摸一秒内只是时间分类，不代表已证明触摸导致了超时。
